# Buildlog MVP

작성일: 2026-10-26

## 1. 제품과 완료 목표

AI와 개발·설정·프롬프팅 문제를 해결하며 얻은 경험을 선별해 지식으로 저장한다. 이후 유사한 문제에서 기존 경험과 근거를 조회해 작업 에이전트에 Markdown으로 제공한다. 사용자는 저장 후 그래프와 연결된 본문을 보며 피드백한다.

완료 흐름: 대화에서 저장 호출 → 경험 선별·정리 → 필요한 조사 → 기존 지식과 연결 → 저장 → 그래프에서 검토·수정 → 다른 세션에서 조회·재사용.

단순 세션 요약에 그치지 않는다. 실제 시도와 결과, 용어의 의미, 원인 분석, 관련 개념과 방법을 함께 남겨 사용자가 경험을 이해하고 학습할 수 있어야 한다.

## 2. 논의로 정한 요구

- 첫 사용 형태는 대화에서 명시적으로 호출하는 스킬이다. 저장 호출 이후에는 후보마다 승인받지 않고 저장을 완료한다.
- 저장 후 그래프를 보고 내용과 관계를 피드백할 수 있어야 한다.
- 프로젝트를 지식의 경계로 삼지 않는다. 프로젝트·환경은 적용 맥락이며 지식은 서로 연결된다.
- 문제 단위로 지식을 나누고 관련 기록을 연결한다. 같은 문제가 다른 세션에서 이어지면 기존 기록을 갱신하거나 후속 기록으로 연결한다.
- 용어와 해당 맥락에서의 정의, 관계와 그 의미를 Markdown에 포함한다.
- 경험은 Mitigation과 RCA 관점에서 정리한다. 상위 프레이밍·관련 연구·사용 방법과 선택 이유를 해당 경험에 연결한다.
- 조회와 작업 에이전트에 대한 Markdown 전달은 MVP 필수 기능이다.
- Antigravity를 필요한 근거 조사의 1차 실행 경로로 사용한다.
- Codex를 우선 실사용 환경으로 삼되 Claude Code에서도 동일한 지식에 접근할 수 있게 설계한다. ChatGPT 연결은 실행 환경에 맞는 별도 연결 경로가 필요하다.
- 선제적 저장 제안은 후속 단계다. 초기 사용 중 사용자의 수정·삭제·추가 피드백을 축적한다.

## 3. Slipbox에서 차용하는 구조

| 구성 | Buildlog에서의 역할 |
| --- | --- |
| 지식 페이지 | 본문을 Markdown 텍스트로 저장하고 사람이 읽고 수정한다. |
| 제목·요약·유형·별칭 | 본문 전체를 읽기 전에 필요한 지식을 찾는다. |
| 목차와 상위 요약 | 지식이 늘어날 때 탐색의 진입점을 제공한다. 프로젝트별 고정 분류는 강제하지 않는다. |
| 구조화된 관계 | 문서 ID를 기준으로 연결·방향·관계 유형을 관리한다. |
| 자연어 관계 설명 | 두 기록이 왜 연결되는지 본문과 조회 결과에 설명한다. |
| DB 정합성 관리 | 문서 수정·이름 변경·관계 변경을 안정적으로 반영한다. |

이 구조는 Slipbox 공개 문서와 인터뷰에서 차용한다. 아래 구현 선택은 Buildlog 설계이며 Slipbox 내부 구현을 복제한다고 주장하지 않는다.

## 4. 구현 결정

Python 3.12 기반 로컬 도구, SQLite 기준 저장소, 로컬 그래프 검토 화면으로 구성한다. 초기 실행은 Windows PowerShell 환경을 지원한다.

SQLite에 Markdown 본문·메타데이터·관계·버전·피드백을 저장한다. 개별 `.md`와 인덱스를 내보낼 수 있게 하며, 에이전트 조회 결과도 Markdown으로 제공한다. DB가 기준 원본이고 내보낸 파일은 읽기·이동·백업용이다. 외부에서 수정한 파일은 명시적 import를 통해 버전을 확인한 뒤 반영한다. DB와 파일을 동시에 독립 원본으로 취급하지 않는다.

별도 그래프 DB·벡터 DB·상시 임베딩 서버는 MVP에 추가하지 않는다. 문서 간 관계 테이블로 그래프를 표현하고 조회한다. 그래프 화면은 같은 DB를 읽고 수정하므로 별도의 그래프 파일과 수동으로 동기화하지 않는다.

기록의 선별·해설·관계 제안은 호출한 작업 에이전트가 수행한다. 저장·검색·관계 검증·버전·렌더링은 코드가 처리한다. 스킬은 작업 지침이며 실제 저장소나 동기화 서비스 자체가 아니다.

## 5. 저장 모델

| 데이터 | 필수 내용 |
| --- | --- |
| 페이지 | UUID, 유형, 제목, 요약, Markdown 본문, 상태, 생성·수정 시각, 버전 |
| 용어 | 표현·별칭, 맥락에 따른 정의, 정의가 있는 페이지 |
| 관계 | 출발·도착 UUID, 유형, 자연어 설명, 근거, 확인 상태 |
| 목차 | 목차 페이지와 구성원, 표시 순서. 순환 계층 금지 |
| 출처 | 세션·파일·URL, 접근 가능한 위치, 관련 구간·발췌, 확보 시각 |
| 변경 이력 | 변경 전후 버전, 변경 이유, 실행 주체 |
| 피드백 | 대상 페이지·관계·버전, 사용자 지적, 적용 변경 |
| 저장 실행 | 요청 ID, 원본 구간 식별값, 처리 결과. 재실행 시 중복 생성 방지 |

페이지 유형은 경험·개념/용어·방법·자료·목차로 시작한다. 용어마다 문서를 기계적으로 생성하지 않는다. 경험을 이해하거나 여러 경험을 연결하는 데 필요한 경우 독립 페이지를 만든다.

관계는 USES, DEPENDS_ON, SUPPORTS, TESTED_BY, DERIVED_FROM, SUPERSEDES, CONTRADICTS, RELATED_TO로 시작한다. 관련 있다는 이유만으로 인과관계를 부여하지 않는다. 모든 관계에 사람이 읽는 설명을 붙인다. 외래키·고유 제약·트랜잭션으로 구조를 보호하고, 관계의 의미와 근거는 에이전트가 정리한다.

## 6. 경험 Markdown의 내용 기준

| 항목 | 기록 기준 |
| --- | --- |
| 문제와 목표 | 무엇을 하려 했고 무엇이 실패했는지, 완료 상태 |
| 환경과 조건 | 도구·버전·OS·계정·실행 방식 등 결과를 바꾼 조건 |
| 용어와 정의 | 이 경험에서 쓰는 용어의 정확한 의미와 범위 |
| 증거와 시도 | 오류 메시지, 명령·설정, 실패/성공한 시도, 관찰 결과 |
| Mitigation | 증상을 완화하거나 작업을 복구한 조치, 적용 조건, 남은 문제 |
| RCA | 원인 가설, 검증 방법, 지지·반박 증거, 확인된 원인 또는 미해결 상태 |
| 개념과 방법 | 상위 프레이밍, 사용한 접근의 정의·선택 이유·적용 한계 |
| 연구와 근거 | 관련 공식 문서·논문·오픈소스 원문과 이 경험에 대한 설명 |
| 관계와 재사용 | 연결 기록, 연결 이유, 재사용 조건과 반례 |
| 출처 | 원본 대화의 관련 구간과 외부 근거 위치 |

Mitigation 성공을 RCA 확정으로 바꾸지 않는다. 미해결 경험도 저장한다. 일반적인 원인을 조사했다는 이유로 이번 경험의 원인으로 단정하지 않는다. AI의 제안과 실제 실행 결과는 시도·검증 상태 안에서 구분한다. 본문은 필요한 정보를 충분히 설명하되 원본 대화 전체를 중복 요약하지 않는다.

## 7. 저장 동작

1. 사용자가 현재 대화에서 저장 스킬을 호출한다. 명시한 구간이 있으면 그 범위, 없으면 현재 접근 가능한 대화에서 재사용 가능한 경험을 선별한다.
2. 기존 제목·별칭·요약·관계를 조회해 신규 기록과 갱신 대상을 결정한다. 확인할 수 없는 과거 세션을 읽은 것처럼 기록하지 않는다.
3. 원본의 증거를 보존하며 경험과 필요한 개념을 정리한다. 대화에 이미 확보된 근거는 재사용한다.
4. 설명에 필요한 근거가 부족하면 Antigravity로 1차 조사한다. 외부 근거는 해당 경험의 개념·방법·검증과 연결한다.
5. 문서·요약·관계·검색 인덱스를 일관된 버전으로 저장한다. 영향을 받는 목차 요약만 갱신한다.
6. 그래프 검토 화면에서 새로 만든 것과 갱신한 것을 강조하고 짧은 저장 결과를 보고한다.

선별 대상은 반복 사용 가능한 해결·실패 경험, 환경 설정의 조건, 원인 분석, 기술 선택의 근거다. 단순 인사·중복 지시·학습 가치 없는 임시 출력은 저장하지 않는다. 자격증명·토큰 등은 제외하고 관련 환경 조건만 남긴다.

## 8. 그래프 검토와 피드백

MVP에 실제 사용 가능한 로컬 그래프 화면을 포함한다. 정적 그림만 내보내는 것으로 완료하지 않는다.

- 노드는 지식 페이지이며 제목·유형·상태를 보여준다. 연결선에는 관계 유형과 방향을 표시한다.
- 노드 선택 시 옆 패널에서 Markdown 본문·용어 정의·출처·변경 이력을 읽는다.
- 연결선 선택 시 연결 이유와 근거를 읽고 수정·해제할 수 있다.
- 제목·본문·용어 정의를 수정하고, 관계 수정·해제·중복 기록 병합을 할 수 있다.
- 대화로도 페이지 ID나 제목을 지정해 수정 요청할 수 있다. 동명이면 후보를 제시한다.
- 최초 화면은 최근 저장한 기록과 주변 관계를 보여준다. 검색과 펼치기로 범위를 넓히고 전체 그래프를 한꺼번에 렌더링하지 않는다.
- 수정은 페이지 버전을 확인해 반영한다. 충돌 시 조용히 덮어쓰지 않는다. 수정 후 요약·인덱스·관계 표시를 함께 갱신한다.
- 피드백을 변경 이력과 함께 축적한다. 이를 자동으로 전역 저장 규칙에 적용하지 않는다.

## 9. 조회와 에이전트 전달

현재 문제 설명으로 제목·별칭·요약·본문을 검색한다. SQLite FTS5를 기반으로 오류 코드·명령·도구명의 일치와 별칭을 활용한다. 한국어 부분 문자열 검색을 보완하며 짧은 검색어에는 별도 일치 경로를 둔다. SQL과 검색식을 안전하게 처리한다.

검색 후보에서 관련 관계와 적용 조건을 확인해 본문을 선택한다. 목차 탐색은 보조 진입점으로 제공한다. 조회의 기본 경로가 깊은 목차를 순차적으로 LLM 호출하는 방식에 의존하지 않도록 한다. 불필요한 원격 LLM 없이 검색·관계 조회·렌더링을 로컬에서 실행하고, 작업 에이전트가 질문의 의미와 적용 여부를 판단한다.

최종 Markdown에는 관련 기록 ID·버전·출처, 당시 환경과 적용 조건, Mitigation과 RCA, 필요한 용어 정의, 연결 이유와 상충·정정 기록을 포함한다. 최신 기록이라는 이유만으로 과거 경험을 폐기하지 않는다. 오래된 방법에는 상태와 대체 기록을 함께 보여준다.

출력 예산은 조정 가능하게 두고, 일부 기록을 생략한 경우 생략 목록과 추가 조회 방법을 명시한다. 근거·적용 조건을 조용히 잘라내지 않는다. 관련 기록이 없으면 없다고 반환하며 외부 조사를 기존 기억으로 위장하지 않는다.

## 10. 실행 환경과 Antigravity 연결

Codex·Claude Code용 스킬은 같은 로컬 도구와 사용자 공통 저장소를 사용한다. 초기 입력은 호출한 에이전트가 접근 가능한 현재 대화다. 각 서비스의 전체 과거 세션을 자동으로 수집하는 기능은 MVP에 포함하지 않는다. 다른 세션 자료는 명시적으로 가져올 수 있게 한다.

Antigravity CLI는 사용자 제공 help에서 `--print`, `--output-format json`, `--json-schema`, `--print-timeout`을 확인했다. 조사 어댑터는 셸 문자열을 조합하지 않고 프로세스 인자 배열로 실행하며, 원문 URL·핵심 근거·관련성을 구조화해 받는다. 인증·웹 접근 성공은 구현 단계에서 실제 실행으로 확인한다. 현재 대화에서 연결에 성공했다고 간주하지 않는다.

Antigravity의 권한 생략 옵션은 사용하지 않는다. 실패하면 기존 경험을 잃지 않게 보존하고 조사 단계를 재개할 수 있게 한다. 조사 실패를 근거 확보 성공으로 보고하지 않는다. 저장 실행과 조사 상태는 분리해 기록한다.

ChatGPT에서 같은 저장소를 읽고 쓰는 경로는 후속 MCP 연결로 확장한다. 스킬 파일만 설치하면 사용자 PC의 저장소·CLI가 자동 연결된다고 가정하지 않는다. Markdown 내보내기·가져오기는 환경 간 이동 경로로 MVP에 제공한다.

## 11. 완료 기준과 구현자가 수행할 검증

| 시나리오 | 통과 조건 |
| --- | --- |
| 혼합 대화 저장 | 여러 문제를 적절히 나누고 실패 시도·환경·근거를 빠뜨리지 않는다. |
| 같은 구간 재저장 | 같은 지식을 중복 생성하지 않고 추가 결과만 반영한다. |
| 원인 미확정 | 복구 성공과 원인 확정을 구별하고 가설을 사실로 바꾸지 않는다. |
| 그래프 피드백 | 잘못된 관계를 수정하면 DB·화면·조회 Markdown에 반영되고 이전 버전이 남는다. |
| 유사 문제 조회 | 다른 표현의 질문과 실제 오류 코드로 과거 기록을 찾아 적용 조건과 함께 전달한다. |
| 반례·정정 | 상충 기록과 대체된 방법을 조회 결과에서 누락하지 않는다. |
| 이름 변경·병합 | UUID 연결을 보존하며 끊어진 참조를 만들지 않는다. |
| 조사 연동 | 실제 agy 조사 결과의 원문 URL을 확인하고 본문에 연결한다. 인증 실패와 시간 초과를 재현해 재개를 확인한다. |
| 규모·성능 | 100·1,000·10,000개 페이지와 관계를 생성해 로컬 검색·렌더링 지연, 화면 응답, 출력 크기를 기록한다. |
| 실제 재사용 | 이전 경험을 모르는 새 세션에서도 제공 Markdown만으로 당시 판단과 적용 조건을 설명할 수 있다. |

성능 수치는 구현 후 측정값으로 보고한다. 검색·관계 조회의 로컬 처리와 조사·에이전트 호출 비용을 분리해 측정한다. 품질 검증에는 실제 경험의 정답 기록과 별도 질문을 사용하며 합성 데이터만으로 의미적 품질을 주장하지 않는다. 이 검증은 구현자가 수행하며 사용자는 그래프에서 결과의 의미를 피드백한다.

## 12. 구현 순서와 MVP 경계

1. 저장 모델·버전·트랜잭션·Markdown 출력 구현 및 최소 Codex 스킬 연결. 실제 대화에서 경험 한 건 정리 → Python CLI로 SQLite 저장 → ID로 읽기 → Markdown 반환까지 확인한다.
2. 인제스트·용어·관계·조인 경로·금칙·미지원 연산과 관련 지식 검색을 확장하고, 스킬 고도화·Claude Code 지원·Antigravity 조사 어댑터를 연결한다.
3. 그래프 검토·본문/관계 수정·피드백 반영을 구현한다.
4. 가져오기/내보내기, 실제 경험의 저장→수정→새 세션 재사용 및 규모 검증을 수행한다.

MVP 완료에는 저장·조회·그래프 피드백의 전체 흐름이 필요하다. 기업용 워크플로 빌더, 다중 사용자 권한, 범용 외부 DB 인제스트, 자동 업무 실행, 선제적 저장 제안은 후속 범위다. Graphify를 직접 설치하거나 내부 의존성으로 사용하는 것은 필수 요건이 아니다.
