# Buildlog 개발 계획

작성일: 2026-10-26 · 기준: mvp.md, prd.md, spec.md 및 이후 사용자 요구

## 1. 실행 원칙

이 계획의 목적은 명세를 실제 사용 가능한 기능으로 연결하는 것이다. 각 Phase는 실행 가능한 결과와 확인 명령·화면을 남긴다. 테스트와 수정은 해당 Phase에 포함하고 마지막 통합 단계로 미루지 않는다.

우선순위: 사용자 최신 요구 → prd.md → spec.md → 기존 mvp.md. 원래 MVP에 빠진 테이블 관계·조인 경로·금칙·미지원 연산은 PRD와 SPEC의 보완 요구에 따라 구현한다. 이 계획은 실행 순서를 정하며 기능 범위를 임의로 축소하지 않는다.

구현 에이전트(2026-10-26 현재 Claude Code)는 저장소·환경을 직접 확인하고 구현·검증·문서 갱신을 책임진다. 도구·라이브러리 선택처럼 조사로 해결할 문제를 사용자에게 돌리지 않는다. 사용자에게는 접근할 수 없는 값이나 제품 선택이 필요한 경우만 질문한다.

첫 구현 전에는 Phase 1 작업과 실제 필요한 사용자 입력을 보고하고 착수 지시를 기다린다. 이후 단계는 사용자의 진행 지시 범위에 따라 수행한다. 단계별 보고는 동작 결과·검증·다음 단계만 간결히 남긴다.

## 2. 전체 순서

| Phase | 목표 | 완료 시 가능한 일 |
| --- | --- | --- |
| 1 | 저장 기반·최소 Claude Code 스킬 연결 | 실제 대화에서 경험 한 건 저장 → ID로 읽기 → Markdown 반환 |
| 2 | 인제스트·검색·스킬 고도화·조사 연결 | 용어·관계·조인·금칙을 포함한 지식을 저장·검색하고 Codex·Antigravity 연동 |
| 3 | 그래프 검토·수정·피드백 | 기록과 관계를 보며 수정하고 다음 조회에 반영 |
| 4 | 이동성·실사용·규모 검증 | 내보내기/가져오기와 새 세션 재사용·복구·성능 검증 완료 |
| 5 | 묶음 소속·작업 공간 화면 | 모든 문서가 목차 묶음에 속하고, 저장된 지식을 목록·세션·소스로 둘러보며 문서와 주변 그래프를 함께 읽고 본문을 고침 |

실제 호스트 스킬 연결을 Phase 1에서 구현한다. Phase 1 검증 호스트는 Claude Code다(2026-10-26 사용자 결정, 원래 Codex). Codex 스킬은 Phase 2.3에서 같은 CLI·저장소 계약으로 연결한다. 이후 기능은 같은 호출 경로에 누적한다. 현재 대화의 AI가 스킬 지침에 따라 접근 가능한 경험을 JSON으로 정리하고, 로컬 Python CLI가 검증·저장한 결과를 같은 AI에 반환한다. Python 프로그램이 대화창이나 과거 세션을 자동으로 읽는 구조가 아니다. Antigravity의 설치·인증 사전 점검도 Phase 1에서 수행한다.

## 3. Phase 1 — Claude Code 스킬 호출 → Python → SQLite → Markdown 반환

### 첫 수행 순서

1. 작업 폴더·AGENTS.md 등 적용 지침·Git 상태·기존 코드를 확인한다. 기존 변경을 보존하고 이미 구현된 기능은 재사용한다.
2. 실제 mvp.md·prd.md·spec.md·plan.md를 읽고 차이를 정리한다. 사용자의 최신 요구를 기준으로 충돌을 해결하고 실행할 Phase 1 범위를 보고한다.
3. 기존 .venv의 Python 버전과 SQLite·FTS5 지원을 확인한다. agy 경로·help·인증 점검 가능 여부도 확인하되 조사 연동은 구현하지 않는다. 사용자의 로그인 조치가 필요하면 구체적인 장애와 조치만 보고한다.
4. 패키지·CLI 실행 구조, 저장 경로 설정, schema_version과 DB 초기화를 구현한다.
5. 최소 pages·sources·evidence·page_sources·revisions·runs 구조와 저장 서비스를 구현한다. 이후 스키마 확장을 위한 migration 경로를 둔다.
6. 최소 입력 JSON 계약과 `python -m buildlog init / ingest / read` 실행 경로를 구현한다. 예시 입력으로 저장 서비스를 먼저 검증한다.
7. 사용자 공통 Claude Code 스킬(`~/.claude/skills/buildlog`)에 저장·읽기 모드를 설치한다. 스킬 지침은 현재 접근 가능한 대화에서 경험 한 건을 정리해 UTF-8 JSON으로 전달하고, CLI 결과를 읽어 사용자에게 반환하도록 한다. 실행기는 설정된 Python 절대 경로를 사용하며 활성화된 셸이나 프로젝트 CWD에 의존하지 않는다.
8. 실제 Claude Code 대화에서 저장 호출 → AI의 경험 정리 → Python 실행 → SQLite 저장 → ID·결과 반환 → 스킬 읽기 호출 → Markdown 반환을 수행한다. 사용자가 JSON을 직접 작성하거나 복사하지 않는다. 이 단계의 읽기는 ID 기반이며 유사 문제 검색은 Phase 2에서 구현한다.
9. 재호출 중복 방지, 버전 충돌, 잘못된 참조의 rollback, 프로세스 재시작 후 재조회까지 검증한다.

### 완료 조건

- 별도 API 키 없이 로컬에서 실행된다.
- 실제 대화의 문제·환경·증거·Mitigation·RCA·출처를 Claude Code가 정리해 저장하고, 같은 대화에서 ID로 읽어 Markdown을 반환한다. fixture와 수동 CLI 테스트만으로 Phase 1을 완료 처리하지 않는다.
- 스킬이 프로그램 실행과 결과 확인까지 수행한다. 사용자에게 JSON 작성·복사나 터미널 명령 실행을 맡기지 않는다. 기록 ID와 DB 경로는 실행 결과로 확인한다.
- 초기 스킬은 경험 한 건의 저장·ID 읽기를 지원한다. 고급 인제스트·검색·Claude Code·외부 조사는 Phase 2, 그래프와 피드백은 Phase 3, 이동성·실사용 완성은 Phase 4에서 확장한다.
- 같은 idempotency_key와 같은 입력을 재실행해도 중복되지 않는다. 같은 key와 다른 입력은 충돌한다.
- 업데이트는 버전과 이력을 남기고 이전 버전을 요구한 수정은 거부한다.
- 유효하지 않은 입력은 부분 저장되지 않는다. 재실행해도 기존 DB를 초기화하지 않는다.
- README에 실제 실행 명령과 결과 예시가 있으며 적용한 테스트가 통과한다.

## 4. Phase 2 — 인제스트·검색·스킬 고도화·조사 연결

아래 세 묶음을 순서대로 구현하고 각각 검증한다. 별도 Phase를 추가하지 않는다.

### 2.1 인제스트·용어·관계·조인·규칙

#### 구현

- 구조화된 저장 계획 스키마와 검증을 확장한다. 원시 대화·문서의 의미 정리는 호스트, 구조 검증·저장은 코드가 담당한다.
- Markdown·텍스트·DDL·schema_json·샘플 입력을 정규화하고 원문 구간·해석 상태를 보존한다. 최초 지원 DDL 방언은 명시하고 미지원 구문은 진단한다.
- 용어의 별칭·맥락별 정의, 문서 간 설명된 관계, 목차·요약을 저장한다.
- 테이블·컬럼·FK·업무상 추정 관계를 연결하고 조인 키·경로·관계 수·NULL·집계 주의점을 보존한다.
- 금칙·필수 조회 조건·미지원 연산에 적용 대상·이유·대안·근거를 연결한다.
- 영향받은 요약만 갱신하고 구조 변경은 트랜잭션으로 처리한다.
- Phase 1의 호스트 스킬이 확장된 저장 계획을 생성하도록 함께 갱신한다. 각 입력 유형은 실제 스킬 호출 경로로 확인한다.

#### 완료 조건

하나의 DB 예제에서 같은 용어의 맥락별 의미, 3개 이상 테이블의 조인 경로, 1:N 중복 집계 주의점, 기간 없는 시계열 조회 금지, 변경 이력 기능 부재를 저장·읽기로 확인한다. 명시된 키·추정 관계·미확인 제약을 혼동하지 않는다. 일반 설정 문제에는 DB 전용 필드를 억지로 생성하지 않는다.

### 2.2 검색·관계 탐색·Markdown 전달

#### 구현

- FTS5 검색, 오류 코드·명령·별칭 일치, 한국어 부분 문자열 보완을 구현한다.
- 환경·시스템 맥락으로 후보를 좁히고 필요한 관계와 정의를 가져온다.
- 저장된 조인 경로와 제한된 후보 경로를 조회한다. 최단 경로를 업무상 정답으로 확정하지 않는다.
- 필수 규칙·상충·대체 기록을 포함해 작업 에이전트용 Markdown을 생성한다.
- 출력 예산과 추가 읽기를 제공하고 핵심 제약을 잘라내지 않는다.
- 기존 호스트 스킬에 검색 모드를 연결해 질의 결과 Markdown을 현재 대화의 작업 맥락으로 읽게 한다.

#### 완료 조건

오류 코드, 다른 표현의 유사 문제, 동명 용어, 반례가 있는 사례로 정답 기록과 필수 규칙이 반환되는지 확인한다. 검색 결과가 없으면 명확히 반환한다. 받은 Markdown만으로 당시 조건·해결책·한계·근거를 이해할 수 있다.

### 2.3 스킬 고도화·Claude Code·Antigravity 연결

#### 구현

- Phase 1과 이 단계에서 확장한 Claude Code 스킬을 고도화하고 Codex용 지침·실행 어댑터를 추가한다. Codex에는 Phase 1 시점의 `~/.codex/skills/buildlog`가 이미 설치돼 있으므로 이를 갱신한다. 두 호스트가 같은 프로그램·공통 DB를 사용한다.
- 초기 저장·ID 읽기를 다시 만드는 단계가 아니다. 확장된 선별·검색·조사 기능의 통합과 호스트 간 재사용을 마무리한다. 그래프 연결은 Phase 3에서 추가한다.
- 실제 agy print 실행과 구조화 결과 수신, 원문 근거 연결을 구현한다.
- 인증·권한·timeout·출력 오류 시 경험을 보존하고 조사 재개를 지원한다.
- 데이터의 요약·개념 추출·관계 제안과 구조적 저장의 책임을 분리한다.

#### 완료 조건

각 호스트에서 같은 저장소에 저장·조회하는 실제 실행을 확인한다. Antigravity로 필요한 근거를 조사해 출처가 연결되고 실패 후 재개된다. 단순히 CLI를 subprocess로 호출했다는 이유만으로 조사 성공을 보고하지 않는다. 사용자가 호출하면 후보별 승인 없이 저장하고 검색한 Markdown을 현재 대화에 전달한다. 그래프 UI 없이도 이 단계의 저장·검색·조사를 검증할 수 있어야 한다.

필요한 사용자 조치는 기존 Antigravity 인증이 실제로 실패할 때의 로그인이다. 추가 유료 API 키·모델은 자동으로 요구하지 않는다. ChatGPT 직접 MCP 연결은 후속 범위를 유지한다.

## 5. Phase 3 — 그래프 검토·본문/관계 수정·피드백

### 구현

- 동일 저장소를 읽는 로컬 서버와 그래프 화면을 구성한다.
- 최근 저장과 주변 관계를 표시하고 검색·필터·주변 펼치기를 제공한다.
- 노드의 본문·정의·출처, 관계의 의미·방향·근거, 테이블과 조인 경로를 표시한다.
- 본문·용어·관계·조인·규칙 수정과 연결 해제·중복 병합을 구현한다.
- 피드백·변경 이력·버전 충돌을 처리한다. 호스트 없이 수정한 본문은 검색에 즉시 반영하고 요약 갱신 상태를 명시한다.
- 저장 스킬의 결과 보고에 실제 그래프 진입점을 추가한다. UI 이전 단계에서는 없는 그래프 주소를 반환하지 않는다.

### 완료 조건

실제 브라우저에서 저장 결과를 보고 관계·정의를 고친 뒤 CLI 조회와 Markdown에 수정이 반영되는지 확인한다. 관계를 해제하거나 기록을 병합해도 참조와 출처를 잃지 않는다. 정적 이미지나 mock 데이터 시연만으로 완료 처리하지 않는다.

## 6. Phase 4 — 가져오기/내보내기·실사용·규모 검증

### 구현·검증

- 사용자와 같은 유형의 설정 경험 및 DB 지식 사례로 저장→그래프 수정→다른 세션 조회를 수행한다.
- 실제 사용 사례에서 검색 누락·잘못된 연결·필수 규칙 누락을 수정한다.

### 저장 흐름 보완 (2026-10-27 추가)

mvp §7 저장 동작 2·3·5단계와 PRD R02·R05에 있지만 Phase 2 저장 절차에 빠진 세 가지를 구현한다. 지금도 검색·기존 페이지 갱신·`concept`/`method` 페이지·관계·목차를 저장할 수 있다. 하지만 스킬의 저장 절차가 이 기능들을 쓰도록 지시하지 않아 실제 저장에서 수행되지 않는다.

- 저장 전 기존 지식 조회: 저장 계획을 쓰기 전에 기존 제목·별칭·요약·관계를 조회한다. 그 결과로 신규 기록, 기존 기록 갱신(`id`+`expected_version`), 후속 기록 연결 중 무엇인지 결정한다. 확인하지 못한 과거 세션을 읽은 것처럼 쓰지 않는다. 의미가 같은지는 호스트가 후보를 비교해 판단한다(spec §2). 판단 결과와 비교한 후보 ID를 저장 결과에 남긴다.
- 상위 개념·방법 연결: 경험을 이해하는 데 필요한 개념·방법을 기존 `concept`·`method` 페이지에서 찾아 관계로 연결하고, 없을 때만 새로 만든다. 용어마다 페이지를 기계적으로 만들지 않는다(mvp §4). 외부 조사 근거를 해당 개념·방법·검증에도 연결한다(mvp §7 4단계).
- 목차 갱신: 저장으로 영향을 받는 목차의 요약만 갱신하고 새 기록을 알맞은 목차에 연결한다(mvp §7 5단계).
- 스킬 Save 절차와 `plan-format.md`를 함께 갱신하고 두 호스트에 재설치한다.

완료 조건: 같은 문제의 후속 시도를 저장하면 새 중복 기록이 생기지 않고 기존 기록이 갱신되거나 후속 관계로 연결된다. 실제 경험 저장에서 관련 개념·방법 페이지와 관계가 생기고, 다음 조회 Markdown에 함께 나온다. 목차 요약이 새 기록을 반영한다. Claude Code와 Codex의 실제 저장 호출로 확인한다.

### 최종 완료 조건

PRD R01–R13의 검증 결과와 실제 실행 근거를 남긴다. 사용자 피드백을 적용한 기록이 새 세션의 작업에 재사용된다. 성능 목표의 달성 여부와 실제 수치를 보고하며 미완성 기능을 완료로 표시하지 않는다. 선제적 저장 제안·범용 DB 커넥터·기업용 워크플로를 추가해 마무리를 지연시키지 않는다.
