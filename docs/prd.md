# Buildlog PRD

버전: 1.0 · 작성일: 2026-10-26

기준: `mvp.md`와 이후 사용자 보완 요구. 이 문서는 제품 요구사항이며 구현은 `spec.md`에 정의한다. 기존 MVP에서 누락된 인제스트 기반 용어 정의·테이블 관계·조인 경로·금칙·미지원 연산을 필수 요구로 보완했다.

## 1. 해결할 문제

AI로 개발·설정·프롬프팅을 수행하면서 얻은 경험이 여러 세션에 흩어진다. 시간이 지나면 문제의 환경·실패 시도·판단 근거가 소실되고, 비슷한 문제가 생겨도 같은 시행착오를 반복한다. 대화 전체 저장만으로는 재사용할 지식을 찾기 어렵다.

Buildlog는 사용자가 저장을 요청하면 경험을 선별하고 지식으로 정리·연결한다. 사용자는 그래프와 본문에서 피드백하고, 다음 작업의 에이전트는 필요한 지식을 Markdown으로 받아 활용한다.

## 2. 사용자와 사용 맥락

주 사용자는 Codex·Claude Code와 함께 개발하고 설정 문제를 해결하는 개인이다. 초기에 Windows·Python 3.12 환경에서 사용한다. 프로젝트 경계 없이 경험과 개념을 연결한다. 프로젝트명은 검색·적용 조건으로만 사용한다.

대표 상황:

1. 복잡한 설정 문제를 해결한 뒤 현재 대화에서 저장을 호출한다.
2. 해결되지 않았더라도 중요한 실패 시도와 원인 가설을 보존한다.
3. 새 세션에서 비슷한 증상을 설명하면 과거 기록과 적용 조건을 가져온다.
4. DB 관련 경험이나 스키마 자료를 넣으면 용어·테이블 관계·조인 경로·조회 제약을 함께 보존한다.
5. 저장 후 그래프에서 잘못된 정의·관계·결론을 고친다.

## 3. 제품 흐름

저장 요청 → 접근 가능한 대화·자료 인제스트 → 기존 지식 조회 → 경험·용어·관계 정리 → 필요한 외부 근거 조사 → 저장 → 그래프 피드백 → 다음 세션에서 조회·Markdown 전달.

한 번 저장을 호출하면 처리와 저장까지 진행한다. 사전 승인 화면을 반복하지 않는다. 완료 후 새 기록·갱신 기록·조사 상태와 그래프 진입점을 알려준다.

## 4. 필수 요구사항

| ID | 요구사항 | 사용자가 얻는 결과 |
| --- | --- | --- |
| R01 | 명시적 저장 호출 | 현재 접근 가능한 대화 또는 지정 자료를 한 번의 요청으로 저장한다. |
| R02 | 경험 선별과 중복 관리 | 문제 단위로 나누고 후속 시도는 기존 경험과 연결한다. |
| R03 | Mitigation·RCA | 복구 조치와 원인 분석을 구분하고 시도·검증·미해결 상태를 보존한다. |
| R04 | 인제스트 기반 용어 정의 | 원문의 표현·약칭·맥락을 분석해 정의하고 해당 자료·테이블·컬럼과 연결한다. |
| R05 | 상위 프레이밍과 근거 | 관련 개념·연구·방법·선택 이유를 경험과 연결해 학습할 수 있다. |
| R06 | 구조와 관계 | 문서·개념뿐 아니라 대상 시스템의 테이블·컬럼·의존 관계를 표현한다. |
| R07 | 조인 경로 | 연결 키, 경로 순서, 관계 수, NULL·중복·집계 주의점을 근거와 함께 확인한다. |
| R08 | 금칙·필수 조건 | 특정 데이터의 조회·해석에 필요한 조건과 금지 행위를 보존한다. |
| R09 | 미지원 연산 | 원본 시스템이 제공하지 않는 API·기능·데이터를 명시해 에이전트가 지어내지 않게 한다. |
| R10 | 그래프 피드백 | 노드와 연결선의 본문·정의·근거를 보고 수정한다. |
| R11 | 조회와 Markdown 전달 | 유사 문제에 필요한 기록·정의·관계·제약을 작업 에이전트에 제공한다. |
| R12 | 버전·이동성 | 수정 이력과 출처를 유지하고 Markdown을 내보내거나 다시 가져온다. |
| R13 | Antigravity 조사 | 필요한 원문 근거를 1차 조사하고 결과를 경험과 연결한다. |

## 5. 인제스트의 의미와 범위

인제스트는 내용을 저장할 뿐 아니라 용어·맥락·구조·규칙을 추출하고 기존 지식과 연결하는 과정이다. 처음에는 현재 대화, 텍스트·Markdown, SQL DDL, 구조화된 스키마·샘플 자료를 입력으로 지원한다. 샘플은 사용자가 제공하거나 작업 에이전트가 이미 허용된 접근으로 확보한 자료를 받는다.

특정 DBMS 전체를 연결하는 범용 커넥터를 요구하지 않지만, 제공된 DB 자료의 용어·관계·조인·제약을 정리하고 재사용하는 기능은 MVP에 포함한다. 스키마 분석과 실제 업무 데이터 조회 실행은 별개다.

약칭이나 데이터 샘플을 바탕으로 추정한 정의는 추정 근거를 남긴다. 명시된 FK와 업무적으로 추정한 조인 관계도 구분한다. 샘플에서 NULL이나 중복이 없었다는 이유만으로 전체 데이터의 제약을 확정하지 않는다.

## 6. 데이터 관련 지식의 필수 내용

| 항목 | 내용 |
| --- | --- |
| 용어 정의 | 표현·별칭·업무 의미·적용 범위와 원문 위치 |
| 테이블·컬럼 | 역할, 식별자, 값의 의미, 단위, 키·NULL 여부 등 확보된 구조 |
| 관계 | 출발/도착 테이블·컬럼, 방향, 의미, 관계 수, 근거 |
| 조인 경로 | 질문의 목적에 맞는 경로와 조인 조건, 필터, 중복 집계 위험 |
| 금칙 | 기간 없는 대량 시계열 조회 등 금지 조건과 이유·대안 |
| 필수 조건 | 기간·사업장·권한·마스킹 등 적용 시 반드시 지킬 조건 |
| 미지원 연산 | 변경 이력·통계·API 등 부재가 확인된 기능, 근거와 가능한 대안 |

이 정보는 그래프 옆 문서 패널과 에이전트에 전달하는 Markdown에 나타나야 한다. 관련 본문만 전달하고 금칙·제약을 빠뜨리는 것은 실패다. 규칙을 저장·전달하는 기능과 외부 DB에서 강제하는 기능은 구분한다.

## 7. 그래프와 피드백 경험

저장 직후에는 생성·갱신된 기록과 주변 관계가 보인다. 노드를 누르면 본문·정의·출처를 읽고, 연결선을 누르면 관계 의미·방향·근거를 읽는다. 검색·필터·주변 펼치기로 범위를 이동한다.

데이터 관련 기록에서는 테이블 관계와 조인 경로를 볼 수 있다. 경로를 선택하면 어떤 컬럼을 연결하고 무엇에 주의해야 하는지 함께 보여준다. 복잡한 그래프를 해석해야만 금칙을 찾을 수 있게 하지 않고 본문에도 명시한다.

본문·정의·관계를 직접 수정하거나 대화에서 수정 요청을 할 수 있다. 잘못된 연결을 해제하고 중복 기록을 병합할 수 있다. 수정 결과는 다음 조회에 반영되며 이전 기록은 이력으로 남는다.

## 8. 조회 경험

사용자가 현재 문제를 설명하면 관련 기록과 적용 조건을 가져온다. 같은 용어라도 환경·테이블별 의미를 구분한다. 과거 방법의 적용 범위, 반례, 정정된 결론을 함께 전달한다.

출력은 작업 에이전트가 읽는 Markdown이다. 필요한 정의·관계·근거·금칙·미지원 연산을 포함한다. 관련 자료가 없으면 없다고 반환한다. 전체 저장소를 매번 입력하지 않는다.

## 9. 완료 기준

| 시나리오 | 통과 조건 | 요구 |
| --- | --- | --- |
| 저장·재저장 | 혼합 대화 분리 및 반복 호출 중복 방지 | R01–R03 |
| 용어 인제스트 | 같은 약칭을 다른 맥락의 정의로 저장하고 출처를 제시 | R04 |
| 근거 연결 | 실제 경험과 조사한 방법론의 연결을 설명 | R05 |
| 스키마 입력 | 테이블·컬럼·명시 FK를 그래프와 본문에 표현 | R06 |
| 조인 경로 | 3개 이상 테이블 경로에서 키·순서·중복/NULL 주의점 전달 | R07 |
| 규칙 전달 | 해당 시계열 기록을 조회할 때 필수 기간 필터를 함께 전달 | R08 |
| 없는 기능 | 부재가 확인된 기능을 미지원으로 표현하고 미확인과 구분 | R09 |
| 피드백 | 본문·관계 수정이 다음 조회에 반영되고 이력 보존 | R10·R12 |
| 새 세션 재사용 | 받은 Markdown으로 당시 환경·조치·근거·제약을 이해 | R11 |
| 외부 조사 | 실제 Antigravity 실행으로 출처를 확보하고 실패 후 재개 | R13 |

구현자는 실제 경험 기반 질의 세트와 별도 합성 규모 데이터로 검증한다. 테스트 결과에는 검색 성공·누락 사례, 지연, 호출·토큰 사용량을 기록한다. 사용자는 결과 의미를 피드백하고 구현·시험 책임은 구현자가 진다.

## 10. 범위와 확장

MVP는 로컬 저장·조회·그래프 수정까지 동작해야 완료다. Codex 우선으로 검증하고 Claude Code에서 같은 도구·저장소를 사용한다. ChatGPT는 Markdown 이동 경로를 제공하고 직접 읽기/쓰기는 후속 MCP 연결로 확장한다.

선제적 저장 제안, 모든 과거 세션 자동 수집, 외부 DB 범용 커넥터, 임의 SQL 실행, 기업용 권한·워크플로 빌더는 후속 범위다. 자료에 포함된 테이블 지식을 인제스트하는 필수 기능을 이 범위 제외로 제거하지 않는다.
